# 历史依赖归档读取

本机默认入口是 `bridge-vfx@bridge-local-v0427-archive`。它按工程恢复必要的历史源码和终态操作/查询回执，并将 MCP 请求交给原字节不变的 0.4.23 消费者。正常操作仍为选择工程、列任务、按原操作 ID 查询；许可、签名、版本和产物校验仍由原消费者执行。

## 保存与读取

- 192 处旧插件包及源码快照（45,682 个文件），加上 85 处终态回执目录（4,078 个文件），共 277 处、49,760 个文件，按 SHA-256 去重为 5,131 份内容。
- 回执仅接受绑定原任务和操作路径的 `COMPLETED` / `FAILED` 记录；含非终态记录的目录保持原位。原 JSON 字节、签名及文件和目录权限完整保留。
- 内容存于 `outputs/Bridge-history-archive-20261113/store/contents.sqlite3`，目录、权限、时间和原路径存于同目录的 `catalog.json`。两者都是必要数据，不能作为缓存删除。
- 读取时恢复普通文件，保留原路径、字节和权限，不使用符号链接或硬链接。原签名文件、许可、账本和工程文件不改写。
- 连续查询复用当前工程的展开缓存。空闲 10 秒、切换工程或关闭连接时，兼容层尝试回收缓存；其他消费者仍在读取时不回收。
- 进入可能保留异步引用的操作时，对应源码和回执目录会留下 `pins` 保留标记。此后不自动解除；必须先核实相关工作已结束，再由操作员安排回收。回执范围内的观察和提案也会先保留展开状态。保留后的回执目录允许新增文件，但已有归档成员必须完整不变；保留目录缺失时拒绝恢复旧副本，以免掩盖新记录丢失。归档恢复本身不授权执行。
- 旧 MCP 消费者仍运行、进程清点不可用、文件被改动或归档校验失败时，拒绝相应回收或读取，不覆盖现场。

当前验证平台为本机 macOS。归档网关不适用于任意目录、正在写入的数据库、密钥或制作缓存；这些材料保持原位。归档目录中的 SQLite 是静态内容仓库，不是旧任务数据库。

## 维护入口

`tools/history_archive.py` 提供 `build / verify / restore / compact / serve`，供操作员维护。普通模型 MCP 工具不接受归档路径，也不提供修改归档、解除保留或重签历史结果的接口。

```sh
python3 tools/history_archive.py verify outputs/Bridge-history-archive-20261113/store
```

需要手动恢复原路径时，先结束归档入口的查询连接，再使用：

```sh
python3 tools/history_archive.py restore outputs/Bridge-history-archive-20261113/store
```

`restore` 是显式恢复，不会永久禁止后续自动回收。若需直接使用旧入口，应先停止归档消费者、完整恢复，再切换默认入口；旧入口本身不会自动解包。

`tools/build_history_gateway.py` 可从已有消费者的路由文档构建本地网关包，归档位置及目录摘要固定在包内。被调用的 0.4.23 安装目录是当前依赖，不能因其默认开关关闭就删除。

旧 0.4.26 入口只能配合 `outputs/Bridge-history-records-20261115/rollback-v0.4.26-store.zip` 中的数据库和清单使用，不能直接用于当前仓库。回滚前先完整恢复当前源码及回执，保留后来新增的文件与保留标记，再更换配套归档和默认入口。

旧 0.4.25 入口绑定更早的目录摘要，不能直接用于当前仓库；它仅能与本机 `rollback-v0.4.25-store.zip` 中保留的原归档配套使用。回滚前必须结束查询连接、完整恢复当前归档的原路径，并核对归档摘要，不能在活动读取期间替换仓库。

GitHub 保存实现、测试和核对摘要；本机内容仓库及原私有状态不随源码上传。

0.4.27 本地切换及历史读回记录见 [历史依赖合并验收](../handover/history-dependency-review-20261115/README.md)。本轮没有提交或同步 GitHub。`outputs/Bridge-history-records-20261115/release-v0.4.27/marketplace` 是已登记的本地插件来源，须与安装目录一并保留。

## 保留标准

只保留旧工程读取、编辑和恢复所需内容。与制作工程无关的历史软件测试及其恢复归档已按用户授权清理，不再提供这些退役测试的原路径恢复。正式工程的主内容仓库、原消费者、默认网关、已登记插件来源、配套回滚包及原签名状态继续保留。

桌面迁入的旧 `bridge-skills` Git 对象已用 Git 原生格式合并；refs、索引和工作区保留，直接使用正常 Git 命令即可读取。

当前清理范围、删除清单和读取验证见 [文件保留与 GitHub 范围](storage-and-publication.md)。`dove-feather-study*` 和核查开始后新增工程均排除在本次清理之外；早期整理报告仅说明各自时点，不再作为已退役测试的恢复操作指南。
