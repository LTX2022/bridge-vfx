# 历史源码归档读取

本机默认入口是 `bridge-vfx@bridge-local-v0425-archive`。它按工程恢复必要的历史源码，并将 MCP 请求交给原字节不变的 0.4.23 消费者。正常操作仍为选择工程、列任务、按原操作 ID 查询；许可、签名、版本和产物校验仍由原消费者执行。

## 保存与读取

- 134 处旧插件包及源码快照的 36,445 个文件，按 SHA-256 去重为 1,012 份内容。
- 内容存于 `outputs/Bridge-history-archive-20261113/store/contents.sqlite3`，目录、权限、时间和原路径存于同目录的 `catalog.json`。两者都是必要数据，不能作为缓存删除。
- 读取时恢复普通文件，保留原路径、字节和权限，不使用符号链接或硬链接。原签名文件、许可、账本和工程文件不改写。
- 连续查询复用当前工程的展开缓存。空闲 10 秒、切换工程或关闭连接时，兼容层尝试回收缓存；其他消费者仍在读取时不回收。
- 进入可能保留异步引用的操作时，对应源码会留下 `pins` 保留标记。此后不自动解除；必须先核实相关工作已结束，再由操作员安排回收。归档恢复本身不授权执行。
- 旧 MCP 消费者仍运行、进程清点不可用、文件被改动或归档校验失败时，拒绝相应回收或读取，不覆盖现场。

当前验证平台为本机 macOS。归档网关不适用于任意目录、正在写入的数据库、密钥或制作缓存；这些材料保持原位。归档目录中的 SQLite 是静态内容仓库，不是旧任务数据库。

## 维护入口

`tools/history_archive.py` 提供 `build / verify / restore / compact / serve`，供操作员维护。普通模型 MCP 工具不接受归档路径，也不提供修改归档、解除保留或重签历史结果的接口。

```sh
python3 tools/history_archive.py verify outputs/Bridge-history-archive-20261113/store
```

需要手动恢复原路径时，先结束归档入口的查询连接，再使用：

```sh
python3 tools/history_archive.py restore outputs/Bridge-history-archive-20261113/store
```

`restore` 是显式恢复，不会永久禁止后续自动回收。若需直接使用旧入口，应先停止归档消费者、完整恢复，再切换默认入口；旧入口本身不会自动解包。

`tools/build_history_gateway.py` 可从已有消费者的路由文档构建本地网关包，归档位置及目录摘要固定在包内。被调用的 0.4.23 安装目录是当前依赖，不能因其默认开关关闭就删除。

GitHub 保存实现、测试和核对摘要；本机内容仓库及原私有状态不随源码上传。相关结果与限制见 [归档读取验收](../handover/history-archive-20261113/README.md)。
