This is reference-reconstruction assistance, not a guarantee that any tutorial can be reproduced. Separate analysis, an established case and an experimental reconstruction. A working modeling/render chain does not prove complex simulation or visual fidelity. For a tutorial, read [tutorial reconstruction](references/tutorial-reconstruction.md) and [verification](references/verification.md) before promising coverage. Preserve the full requested effect while staging bounded work; do not turn a simpler diagnostic into the final target.

Read-only assessment does not require starting a DCC. Check the active catalog before proposing execution: a description or bundled reference does not expose a missing action. An operator-worker result proves only that execution route, not autonomous production through this model-facing entry. Continue routine authorized steps without repeated approval questions; honor the active task's cumulative stop conditions.

For matching geometry, feedback and recovery cases, consult [production and feedback lessons](references/production-feedback-lessons.md). For packaging or controller/artifact handoff failures, consult [engineering lessons](references/engineering-lessons.md). Their case evidence does not establish current route or full-shot support.

For existing registered projects, call `bridge_projects`, explicitly select a project with `bridge_select_project`, then use `bridge_tasks` and `bridge_continue_task` with its project and original operation IDs. Reconnection requires an explicit selection again. Completed tasks return original verified files; running tasks are observed; failed or unknown work stays blocked without a new dispatch. The directly configured GraphMCP connection below remains available for graph editing. Historical deliveries are read-only and cannot become new execution inputs. Do not call `bridge_connect` just to retrieve completed tasks.

To start an independent task from an existing accepted geometry project, first select its source project and list tasks. Call `bridge_create_task` with that source project, one explicit completed operation ID, your new goal, and one stable request ID. If the create response is lost or times out, query `bridge_creation_status` with the exact original request_id, source_project_id, source_operation_id and goal; select the original source first after reconnecting. READY returns the original task. UNKNOWN/INTENT and NOT_FOUND never authorize a replacement request. Use the returned new project/task IDs; never reuse a source scope or change the request ID after an uncertain result. The initial supported profile is `geometry_from_existing_v1`; other source kinds are explicitly unsupported. Select the new project and use catalog/media/observe/propose. Source geometry is a baseline; submit your own bounded model proposal. Creation starts no DCC and grants no native execution permission. The new `geometry_task` kind requires a separate operator-issued execution grant before `bridge_execute`; do not work around a missing grant or downgrade its registration kind. Operator configuration and authorization are CLI actions, not model MCP tools.

For an explicitly prepared `rectlight_shape` project, use the registered project/catalog/media/observe/propose/execute/continue workflow below without an extra background connection. Its authorized jobs start and account their own hosts. Propose only the `rectlight_shape` width/height pair from the catalog; preserve area, exposure and the fixed rig. Inspect the actual first preview before choosing a distinct second ratio.

An operator may bind a finite task template when configuring creation. Read the selected project's public brief, feedback and `catalog.goal_contract`; the proposal's `goal` text does not change its registered evaluation criteria. The current additional template is a five-part table exercise using the existing bounded Box/Transform/Merge/Output catalog. Generated task drawings are learning references, not official tutorial images. A `source_preview` documents the reused source scene and does not prescribe the new model. Template selection and replacement remain operator actions; models cannot submit paths or change evaluation criteria through MCP.

For a task that needs a real independent background DCC connection, use the default installed entry: call `bridge_health`, then `bridge_connect` with one stable `request_id`. The agent supplies this ID; the user does not supply paths, ports, tokens or setup scripts. This starts at most one independent background Houdini 21.0.631 and Nuke 17.0v1 for that request, using the installed runtime and private host configuration. Use `bridge_connection_status` with the returned `connection_id`; report connected only when the overall state is `CONNECTED` after both real host health checks succeed. `bridge_health` returning `READY` means `entry_ready:true` and `dcc_connected:not_checked`; it neither launches nor probes DCCs.

The background connection has a fixed 120-second maximum lifetime, ending at the earlier signed host start time plus 120 seconds. Repeating the same request, checking status or reconnecting the MCP transport never renews it or restarts a host. An expired or failed connection is never restarted automatically; a new connection needs an explicit `bridge_connect` with a new request ID within the authorized task. Call `bridge_disconnect` when finished; it stops only this connection's owned background hosts. Closing MCP leaves the hosts to their existing lease. Connecting does not open an old project, recover failed work or authorize rendering.

For an explicitly authorized geometry project, use `bridge_catalog` to read the current revision, public brief and limited model schema. A result with `state:COMPLETE` confirms the technical delivery; check `goal_status` and `goal_evaluation` separately. `goal_status:FAIL` means the requested geometry target was not met, and `UNKNOWN` has no verified goal outcome. Human visual acceptance remains separate. Read `catalog.observation_requirements.required_asset_ids`. Fetch every listed asset with `bridge_media`, actually view its image and submit your own `bridge_observe` description. Include the returned IDs covering every required image in `bridge_propose`; the first version includes the source preview when registered, and feedback requires its registered full and local render previews. Use catalog asset IDs rather than result file keys. Supply `goal`, `rationale`, and `observation_ids`. Feedback uses `edits` entries containing exactly `node_id` and `parms`; use the exact IDs and parameter names in `catalog.editable_nodes`, not qualified connection references. Use the tool error diagnostics to correct missing public inputs. Submit a finite first model or versioned parameter edits with `bridge_propose`; only `bridge_execute` dispatches the accepted plan. Reconnect by selecting the same project and querying the original operation. Historical accepted results are observation only; an unknown operation is never redispatched. Keep fixed camera, lighting, material and render rig outside model edits.

After two accepted geometry revisions, the same project supports additional edit proposals using the current revision and its `preview_N` / `local_N` media from the catalog. Every further execution requires an operator `authorize-feedback` grant bound to that exact saved plan and one stable execution request. Each grant permits one dispatch with five downstream starts, 900 seconds and 512 MiB; it does not reset the original grant or allow graph/alpha work. A repeated execution request observes the original operation, including UNKNOWN; changing the request ID does not authorize another dispatch. Evaluate the requested geometry against the original accepted baseline specified by the project. The catalog and tasks include accepted supplemental revisions without rewriting the original two-revision state.

Query `health` and `graph_catalog`, then follow the existing [workflow](references/workflow.md). For a tutorial or inherited failed scene, read [tutorial reconstruction](references/tutorial-reconstruction.md) before planning edits. Read the relevant [domain reference index](references/domains/INDEX.md) on demand; use registered capabilities and actual tool schemas instead of inventing controls.

Use registered media tools for observations and preserve uncertainty. Follow existing request identity, graph version, scene ownership, approval and artifact rules. Missing configuration or product semantics is a blocking gap; an installed plugin is not a production acceptance result.

Operator setup is in [plugin setup](../../docs/agent-plugin.md). Diagnostic health and catalog queries do not start a real DCC and cannot establish provider, model, native-host or visual acceptance.

For an operator-registered `geometry_delivery` project, select it and use tasks/continue to accept or retrieve its verified files. Its catalog is read-only; do not propose, execute, cancel, or use it as a new-task source. The original failed operations remain blocked. Independent cold-rendered files do not imply the old C2 operation succeeded.
