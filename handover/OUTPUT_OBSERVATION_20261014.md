## 实现与复现

1. `_fx_render_configuration` 对 storage、multipart、compression 改为每个目标帧单次 `Attribute.Get(frame)`，保存已校验的同一值。核对 USD 声明类型和 Python 实际类型，拒绝 bool/float 冒充 int、空值、容器、错误类型与不支持的格式；原生读取异常转换为 `RENDER_CONFIG_INVALID`。采集不改变当前 Houdini 帧。
2. `render_color_facts` 的完整观察共用 2,097,152 字节及 32,768 次值/工作预算。数组在读取元素前计入结构和工作量，名字、类型、路径、缺口和正常值均计入预算；最终流式 JSON 检查包含 UTF-8、ASCII 转义及结构开销。超限中止整次采集，不把截断内容当作有效事实；预算异常穿过内部捕获并由正式 addon 拒绝。controller-entry 副本逐字节同步。
3. 诊断只保存有界异常类名和固定说明，不调用原生异常的 `str()` 或保留正文。正常17-AOV、合法128次遍历及原有独有故障/竞态断言保留。已知超预算观察在完整 USD 导出之前拒绝。

修复前的当前正式入口通过实际图试验/交接、保存与重开后，请求第3帧；底层 USD 默认压缩有效，时间样本为不支持的 DWAA。入口没有按目标帧拒绝，独立冻结基线退出1，`BridgeError not raised`。原始日志保留，不改为通过。只读发现还实际复现了约4.2 MiB的合法数组观察及超长异常正文。

该上限只约束单次返回的颜色观察及其 Python 采集工作；不宣称原生 API 返回对象/耗时、整个 USD stage、全帧配置/操作记录或生产峰值内存都有相同上限。
