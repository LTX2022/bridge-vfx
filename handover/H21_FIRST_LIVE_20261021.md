## 实际输出与失败点

真实文件：[alpha-chart.exr](evidence/20261021-first-live/alpha-chart.exr)，76,629字节，SHA-256 `158bc351385db19453b117eb78d5dd087354645d15f692b9244cc9c29e1435c0`。

生产 EXR 解码器完整解码成功：128×128、无压缩，但只有一个 float32 通道 **C.R**，全部16,384个数值均为0。不存在 G、B、A，不能完成透明、半透明与不透明区域的 alpha 校准。

Driver 在 `run_alpha_calibration.py:437` 调用 `_decoded` 后，由 `controlled_output.py:89` 按冻结 RGBA 合同拒绝，错误为 `CONTROLLED_OUTPUT_EXR_OUTSIDE_POLICY`，driver退出码1。没有放宽合同，也没有把进程退出0当作输出验收通过。

冻结 USDA 同时声明 `dataType="color4f"` 与 `driver:parameters:aov:husk:format="float"`（`prepare_native_alpha_scene.py:152`）。同版本机 `husd/karmautils.py:425` 将后者设置为 precision，`:487–489` 对 color4 默认使用 color4h。真实日志还记录“Variance oracle needs C to be 3 (not 1)”。这是首个明确的输出配置不一致；尚未修改或重新渲染，不能声称修后已通过。

软件夹具 `engineering_houdini_api_fixture.py` 直接生成 RGBA 数值，没有执行 husk 对该 format 的原生解释，因此此前软件通过没有覆盖这一事实。

[单通道诊断预览](evidence/20261021-first-live/alpha-chart-C.R-diagnostic.png)只显示实际 C.R 数据，不是合格 RGBA 或最终球体效果。
