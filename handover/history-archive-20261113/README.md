## 读取验收

- 全新安装的 0.4.25 消费者通过正常 MCP 查询入口选择默认目录全部 **9 个工程，读回 14 个 COMPLETE 结果**。
- 14 份返回内容与原 0.4.23 读取结果逐项一致，包括原结果摘要、文件、目标状态及历史可消费边界；原 PASS／FAIL／UNKNOWN 不被改写。
- 实际空闲回收测试：读取 DiskLight 时恢复 47 处依赖，空闲约 **17.1 秒**后全部回收；再次查询自动恢复，返回同一原结果。连接退出后再次全部回收。
- 18 项定向软件检查通过，覆盖内容去重、原路径恢复、摘要异常、链接拒绝、共享读取锁、旧连接保护、按工程保留、空闲回收及中断删除恢复。
- 569 个保护文件摘要均未改变；原 0.4.23 的 431 个清单成员、新入口的 47 个清单成员校验通过。
- 归档全部成员重新解压校验通过。收尾时没有展开根目录或未完成删除项。本轮原生执行工具调用为 **0**，未重跑建模、冷开或渲染。

本轮按用户授权结束旧 MCP 连接；客户端随后自动重连的一个旧连接也已核实身份并结束。旧连接存在时保护机制拒绝回收，这一观察单独保存于 `legacy-guard-observation.json`。旧聊天再次使用 Bridge 时需重连，Houdini／Nuke 未因本次切换被关闭。

## 保留边界与维护

剩余文件仍包括原工程、产物、素材、数据库、许可、签名、失败记录、未迁入本仓库的依赖以及已退役环境归档。此次没有把全部历史依赖统一替换成新版运行时，也没有改写旧签名。知识总结不能替代这些数据。

源码恢复使用普通文件，保持原路径、字节与权限。连续查询复用展开缓存；空闲 10 秒后开始尝试回收，实际耗时还包括核验和删除。异步操作关联源码会保留 `pins`，不能仅凭进程退出就自动清除。旧消费者仍运行、进程检查不可用或文件被改动时保留现场。

验证范围为当前 macOS、默认登记目录及上述只读操作。未重新验证原生制作、任意教程复现、视觉质量、其他平台或独立登记目录。维护和手动恢复方法见 [历史源码归档读取](../../docs/history-archive.md)。

GitHub 保存本次实现、测试、维护文档及选定核对摘要；内容仓库、详细原始回执及私有状态保留本机，克隆仓库不构成完整历史恢复。

机器可读摘要：`acceptance-summary.json`、`readback-summary.json`、`storage-final.json`、`inventory-reconciliation.json`、`package-integrity.json`、`protected-final.json`、`idle-readback.json`。完整查询回执保留本机 `final-installed-readback.json`。
