## 根因与软件修复

真实 traceback 给出了 adapter 的完整绝对编译文件路径，但原生 exec namespace 没有 `__file__`。此前软件 Husk 夹具使用 `runpy.run_path`，自动补入该名称，掩盖了这个环境差异。此处是脚本与夹具的错误假设，不是 vmmap 超时或身份门过严。

最小修复只涉及四个文件：authoritative adapter、其 controller 镜像、Husk 软件 API 夹具及一份已有测试模块。

- adapter 用当前帧 `f_code.co_filename` 定位实际编译来源，拒绝相对、非规范、错误名称、链接、缺失邻接文件或多硬链接来源，再沿原 `runpy` 路径调用同一 ready helper。
- fixture 改为以真实绝对脚本路径 `compile/exec`，namespace 不含 `__file__`；不自行生成成功身份或就绪事实。
- `owned_process`、身份、状态机、准入、预算及 deadline 源码未改。tool5/freeze5/observe16/collection22/capture60、HMAC/PID/nonce、原完整 OS proof 及停止门保持。

H21 本机 Python 3.11 `inspect.py` 与 [Python 3.11 官方代码对象文档](https://docs.python.org/3.11/reference/datamodel.html#codeobject.co_filename)提供来源依据；实际 traceback 证明本次 native compile filename 为该绝对路径。[依据与同因排查](evidence/20261023-h21-live-14/husk-filename-fix-go.md)没有发现需要扩大修改的其他 Husk hook 入口。
