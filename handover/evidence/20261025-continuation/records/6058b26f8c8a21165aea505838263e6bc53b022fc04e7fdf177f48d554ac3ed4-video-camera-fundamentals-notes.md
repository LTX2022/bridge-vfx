## 1. 容器 / 流 / 编解码器概念（ffmpeg 语境）

| 概念 | 定义 |
|---|---|
| 容器 Container | 文件格式：`mp4 / mkv / mov / avi / flv`，含 5 种流 + 文件头 |
| 流 Stream | `音频、视频、字幕、附件、数据` 5 种 |
| 包 Packet | 已编码好的一个单位音频/视频 |
| 帧 Frame | 一幅静止图像（YUV 数据）或若干音频采样 |
| 编解码器 Codec | 压缩/解压缩，`CODEC = ENCode + DECode` |
| 复用/解复用 mux/demux | 流按容器规则打包 / 从容器解析出流 |

- 视频编码标准谱系：`H.261/262/263`（ITU-T）→ `MPEG-1/2/4 part2`（ISO-IEC）
  → 两家联合 JVT 于 2003 发布 **H.264/AVC** → **H.265/HEVC**
- `H.265/HEVC`：体积更小画质更好；**Windows 默认不带 H.265 解码**
- `AV1`（AOMedia Video1）：开源免费，前景好
- `mp4` 双平台兼容、`mov` 更适合苹果；整理素材最有效率是 H.264
- 编码参数：`码率 Bitrate / Profile / Level / GOP`；码率控制 `CBR`（固定）、
  `VBR`（可变）、`CQ`（恒定画质）
- 软编：慢但画质好；硬编：快但画质较差
- 电视台播出标准参考：CBR，码率 15 Mbps（15000）

## 2. 片源命名术语速查（拿到素材先读懂文件名）

格式：`片名.年份.片源.平台.视频编码.音频编码.压制组`

- 片源：`BluRay`（蓝光压缩）/ `BluRay.Remux`（蓝光原盘无损提取）/
  `WEB-DL`（流媒体）/ `WEBRip` / `UHD`（4K）
- 平台：`MA` / `NF`（奈飞）/ `ATVP`（Apple TV+）/ `DSNP`（Disney+）/
  `HMAX` / `iT`（iTunes）/ `AMZN`（亚马逊）
- 视频：`HEVC`=H.265、`x265`=H.265 编码器、`10bit` 色深、
  `HDR` 一般指 HDR10、`DV` 一般指杜比视界 P5、
  `DV.HDR` 一般指 P8（向下兼容 HDR10）
- 音频：`TrueHD`（杜比无损）、`DDP/DD+`（杜比数字+ 有损）、`Atmos`（全景声
  元数据）、`DTS / DTS-HDMA / DTS:X`、`7.1/5.1` 声道
- `IMAX`：1.90/1.89/1.85:1 画幅版本（多数影片仅部分场景 IMAX，其余 2.39:1）

## 3. 帧率 / 制式 / 场 / 时间码

- **PAL**：逐行倒相正交平衡调幅制（1962 西德），克服 NTSC 相位失真；
  **PAL-D 是中国大陆制式**；**帧频 25fps，场频 50 场/秒**
  - 国内交流电 50Hz → 用 25 帧 + 1/50 快门拍摄可规避灯光频闪
- **NTSC**：1952 美国；**帧频 29.97fps，场频 60 场/秒**；有色彩失真缺陷
- **SECAM**：法国 1956 提出；顺序传送彩色与存储恢复；色彩保真高、兼容性差
- **场**：隔行扫描一帧 = 奇数场 + 偶数场两个"半帧"；逐行扫描一帧 = 一个完整
  垂直扫描场。`p` = 逐行，`i` = 隔行（i 已基本不通用）
- 行业帧率惯例：电影 **24fps**；电视剧/CG 宣传片 **25fps**；国内广告 **29.97fps**；
  自媒体现推荐 29.97/59.94（29.97、59.94 帧的视频在设备上不卡）
- **时间码 SMPTE**：`时:分:秒:帧`。例：PAL 素材 `00:01:30:13` = 持续
  1 分 30 秒 12 帧 ≈ **2263 帧**（25fps 下约 1 分 30.5 秒）
- **像素长宽比（PAR）**：一般 1:1 正方形像素；**变形宽银幕素材可能是 1:1.5 或
  1:2**——合成时先确认 PAR 再干活

### 混合帧率处理（达芬奇做法，思路通用）

- 30fps 素材进 24fps 工程：素材`片段属性`里帧率选 **30**（保持原速解释），
  工程 24——软件做抽帧
- 若素材帧率也改成 24，会**音画不同步、播放变缓**
- 变速补帧三法（质量递增）：`最近`（取接近帧，易卡顿）→ `帧混合`（前后帧
  混出模糊中间帧，适合快放）→ `光流`（算像素运动生成新帧，适合慢放、
  要求背景干净）。Nuke 侧对应 `Retime` / `Kronos` / `OFlow`

## 4. 分辨率标准

- **DCI 4K = 4096×2160**（电影放映标准，2004）；DCI 2K = 2048×1080
- **UHD 4K = 3840×2160**（电视标准，2012）；UHD 2K = 1920×1080
- 两者横向像素不同，混项目时 Reformat 别搞错基准
- HD = 720p 及以上；FHD = 1080p 及以上
- `p/i` 是显示器/电视行业术语，`K` 是电影行业术语（互联网已混用）
- 目前电影主流交付规格 **2K DCI 24 帧**；国际电影节放映普遍要求 **2K DCP**
- 位分辨率（位深）：每像素存储位数——8/10/16/32 位

## 5. 色度采样与位深（合成素材质量判断）

**色度二次采样（Chroma Subsampling）**（截图见原笔记 `微信截图_20240303234032.png`）：

- 记法 `4:2:0`：像素行宽 4；顶行有 2 个像素采集色彩；底行 0 个
- `4:2:0`：顶行 4 像素中 2 个采色，底行不采——周围像素**拉伸共用**色度信息
- `4:2:2`：顶行 2 + 底行 2，仍有轻微拉伸
- `4:4:4`：全部像素都采色
- **合成影响**：绿幕抠像、限定器选肤色在 4:2:0 素材上边缘会糊——
  能要 4:2:2/4:4:4 就不要 4:2:0

**位深**：

- 8bit：每通道 2^8 = 256 级 → RGB 共 **16,777,216** 色
- 10bit：超过 **10 亿**色（HDR 最低要求）
- 12bit：每通道 4096 级 → 超过 **680 亿**色
- 位深越高，调色、限定肤色、绿幕抠像越容易

## 6. Log 与 RAW 速查（合成师接素材必备）

`Log` = Logarithmic，对数曝光曲线记录模式：压低高光、提升阴影，
从传感器捕捉尽可能宽的动态范围；白平衡/ISO/对比度已在机内固化，
**前期必须保证白平衡和曝光正确**。

| 厂商 | Log | RAW |
|---|---|---|
| Sony | S-Log（S-Log3） | X-OCN |
| Canon | Canon-Log (C-Log) | — |
| RED | Film log / RedLog / RedGamma | REDraw（.R3D） |
| Arri | Log-C | arriraw |
| 松下 | V-Log | ProResRAW（国造/大疆/松下也用） |
| 大疆 | D-Log | — |
| 富士 | F-Log | — |
| 尼康 | N-Log / Z-Log | Nraw |
| 徕卡 | L-Log | — |
| BMD | BMDlog | BRAW |
| ZCAM | — | ZRAW |

**RAW**：原始传感器数据，**未经解拜耳（de-Bayer）**；后期可无损改白平衡、
ISO、曝光、色彩空间（曝光值/色彩空间/gamma 都是可变的，不像编码视频是静态的）。

**解拜耳时机与中间格式**：
1. **优化媒体**（达芬奇/FCPX 叫优化媒体，PR 叫代理 Proxy，AVID 叫动态重链接）：
   转码为轻量内置编码，适合自剪自调
2. **代理转码**：ProRes LT / DNxHD（Rec.709），外包调色用
3. **Mezzanine 中间格式**：`OpenEXR / DPX / ProRes 4444`——**大量 VFX/CG
   项目的标准做法**，建立严格色彩管线保持供应商间一致；前提是各方在
   CDL、LUT、色彩空间转换上保持一致

## 7. 相机参数与合成的关系

### 快门（与动态模糊直接相关）

- **180° 快门规则：快门分母 ≈ 帧率 × 2**。24fps → 1/50s；60fps → 1/120s
- **快门不能超过帧率 4 倍**，否则运动画面缺动态模糊、观感一卡一卡
- 快门整档：`30s … 1s、1/2、1/4、1/8、1/15、1/30、1/60、1/125、1/250、
  1/500、1/1000、1/2000、1/4000、1/8000`，相邻整档 2 倍关系
- 合成启示：素材动态模糊不足时别硬加 VectorBlur 冒充——先确认前期快门；
  降快门（1/2000→1/1000→1/500）可糊掉螺旋桨/灯光频闪

### 光圈 / ISO / ND / 光比

- 光圈整档：`1 1.4 2 2.8 4 5.6 8 11 16 22`；数值大 = 孔径小
- **T 值 vs F 值**：F 值 = 焦距/孔径（理论值）；T 值 = 实际通光量（电影镜头
  标准）。T ≥ F，差值 = 光在镜组中的流失；T 越接近 F 透光越好
- ISO 整档：`100 200 400 800 1600 3200 6400 12800`，每档 ×2；
  ISO 100→400 需其他参数降两档补偿（如 1/125s→1/500s）
- ND 滤镜：`0.3=降 1 档、0.6=降 2 档、0.9=降 3 档`（规律：0.3/档）
- 光比：1 档=2:1、1.5 档=3:1、2 档=4:1、3 档=8:1、4 档=16:1、5 档=32:1；
  人像常用 3:1 / 4:1
- M 档思路：光圈控**景深**、快门控**动态模糊**；人像安全快门 = 等效焦距倒数
- 阳光 16 法则（胶片机）：光圈 晴 16 / 阴 8 / 多云 11 / 日暮 4，快门 = ISO 倒数

### 果冻效应与摩尔纹（后期基本修不了，前期防）

- **果冻效应**：CMOS 电子卷帘**逐行读取**，快门与被摄体速度差越大越明显
  - 前期：机身倾斜 45° 再后期旋转裁切（需高分辨率）；高 ISO + 大光圈换高快门；
    全域快门/加快读取速度/像素合并
  - 软件：gyroflow（需相机陀螺仪 + 镜头数据）
- **摩尔纹**：本质是**香农-奈奎斯特采样定理**——采样频率 < 信号频率 2 倍时
  混叠，高频纹理被低频替代。纹理密集 = 高频信息
  - 前期：倾斜旋转一点角度、改焦距避开频率区间、OLPF 光学低通滤镜（会糊一点）
  - **后期没办法修**，只能降一半锐化 + 中间调拉高遮一遮

## 8. 索尼体系实例（FX30，理解相机菜单的样板）

- 制式：60Hz = NTSC，50Hz = PAL（中国）
- **双原生 ISO**：`800`（高动态范围）/ `2500`（底噪最优）——合成师拿到夜景
  噪点多的素材，先问是不是没卡在原生 ISO 上
- 图片配置文件：`PP8` = S-Log3 的 Cine 版，`PP9` = S-Log3 标准版
- **S-Gamut 色域**（截图见原笔记 `索尼色彩空间.jpg`）：
  - `S-Gamut / S-Gamut3`：比 S-Gamut3.Cine 更大（两者范围相同，3 代色彩再现更好）
  - `S-Gamut3.Cine`：略大于 DCI-P3；配 S-Log3 灰阶近似胶片负片扫描
- **S-Cinetone**：类威尼斯电影外观、优化肤色；动态范围**低于** S-Log3，
  但动态范围/噪点平衡最佳（直出好，不适合大调）
- `HLG1` 暗部好 / `HLG2` 均衡 / `HLG3` 高光；HLG1 拍夜景高感好，
  S-Log 拍夜景对曝光要求高
- **Cine EI 显示**：如 `800EI/6.0E/L`——第二个数值 = 给**亮区**（高于 18% 灰）
  分配的档数（6.0E = 亮侧 6 档，再高即过曝）；L=低感 H=高感
- **XAVC 家族**：
  - `XAVC HS 4K`：HEVC（H.265）Long GOP，压缩率最高
  - `XAVC S 4K/HD`：H.264 Long GOP，多帧压成一组，后期空间有损失
  - `XAVC S-I 4K/HD/DCI 4K`：**Intra（ALL-I）逐帧独立压缩**，文件大但剪辑
    不吃力、最适合后期
  - `AVCHD`：约 25-28 Mbps，H.264，广播级要求 50 Mbps
  - 规律：**Intra 按帧压缩（编辑灵活） vs Long GOP 多帧压缩（体积小）**
- `S&Q` 慢动作：**录不进声音**

## 9. 变形宽银幕（Anamorphic）与后期还原

- 特点：**椭圆焦外光斑、水平眩光拉丝、变宽画面**（强光源冲光时拉丝明显）

## 11. 动态范围测试（理解 DR 标称值）

- 四种定义：绝对理论 / 目视测量 / 普适标准 / 实用宽容度（截图见原笔记）
- **`DSC Labs XYLA 21`** 标准测试卡：21 个逐档背光格；过曝从第二格空缺处起算
- 实测法：挡板遮住暗部 → 波形对到中灰位置 → 抽挡板看明暗分布；
  量化用 imatest，关注 `Slope-based DR`（Low/Med/M-H/High）与 **SNR**
- SNR 1:2 标准：斜率低于密度响应曲线最大斜率 **7.5%** 后不计入成绩
- 测试规范：50mm+ 无极光圈镜头、色温 **3700K**、略微虚焦、关闭机内一切
  不可逆处理

## 12. 前期拍摄对后期的影响（合成师该向前期要什么）

- **不要删任何素材**，废条跑条都不删，文件号连贯；拷贝期间不动硬盘和线
- 摄影机设置建议：**4K、ProRes 422HQ 以上**（不支持 ProRes 就同级别）
- 喊"卡"后多录 3-4 秒再关机（剪辑要气口）；喊"开始"后演员酝酿 2 秒
- 升格：24/25fps 下预感要减速的画面**该升格就升格**，别指望后期光流补帧
  （有几率大翻车）
- 老机器统一**逐行扫描**，不要一部分隔行一部分逐行
- 机头麦一直开：时码出问题时靠声波分析找回同步
- 打板仍是硬保险（时码器也可能两帧错位）
- 多机位：卡号分 A/B/C 机（A001C001 / B001C001）
- 夜景建议拍灰片（Log）：夜景光比常比白天大，不拍灰片灯光一片死白、
  过曝边缘生硬红白；噪点问题用原生感光度解决
- 滤镜对合成的影响：CPL 消反光（玻璃/水面）；黑柔保留对比度+扼制暗部发灰、
  白柔降对比朦胧；ND 保 180° 快门；**VND 调大了有十字纹+偏色**（素材若有
  十字纹，知道是 VND 背锅）

## 13. 镜头光学瑕疵速读（做镜头匹配/镜头效果时）

- 焦外光斑诊断：彩虹边缘 = 色差（紫边绿边）；不圆 = 像散；拖尾 = 慧差；
  中心边缘大小不一 = 场曲/畸变；缺损 = 会暗角；分层不均 = 非球面镜片
- **光斑大小与光源大小无关，只与离焦距离有关**
- 二线散景（焦外二线性）：光斑边缘两条刀锋亮线、像泡泡

## 易错点

- **DCI 4K 与 UHD 4K 混淆**：4096 vs 3840，横向差 256 像素；跨项目 Reformat
  基准写错会全员对不上
- **PAR 没确认就开工**：变形宽银幕素材按 1:1 像素合成，所有跟踪/roto 全废；
  先看像素长宽比
- **混合帧率直接改素材帧率**：30 帧素材标成 24 帧 = 慢放 + 音画不同步；
  要保持原速解释再让工程去适配
- **4:2:0 素材硬抠绿幕**：色度是拉伸共用的，边缘必然糊；先要高质量版本，
  或接受边缘缩边处理
- **快门角度错觉**：以为快门越快越"清晰专业"——超过帧率 4 倍就没有动态模糊，
  运动感一卡一卡；也补不出真实运动模糊
- **果冻/摩尔纹指望后期修**：两者本质上都修不了（逐行读取、采样混叠），
  拿到这种素材只能遮掩，前期倾斜 45° 才是正解
- **S-Log 夜景当白天拍**：S-Log 夜景对曝光要求极高，不卡在双原生 ISO
  （FX30: 800/2500）上噪点爆炸；夜景高感优先 HLG1
- **S&Q 素材找声音**：S&Q 慢动作机内不录音，别当素材丢了
- **Cine EI 读数误读**：`800EI/6.0E/L` 的 6.0E 是亮部分配档数不是总动态范围
- **Long GOP 素材直接做精细 roto/跟踪**：帧间压缩，单帧质量不如 Intra；
  精细活前先转 Intra/EXR 中间格式（Mezzanine 思路）
- **VND 十字纹误判**：素材出现十字交叉纹 + 偏色，是 VND 档位过大，不是素材坏了
- **光斑大小归因错误**：光斑大小只跟离焦距离有关，跟光源大小无关——做
  景深匹配时按离焦量算
