# HIP path identity implementation

Production change is limited to task HIP reopen, its durable transition binding, replay and interrupted-intent proof. The two snapshot-load paths now share one `setName(original_path)` and normalized path readback outside the load exception handler. Registration receives the original path and unchanged SHA. Requested SHA is checked before loading. No save, compensating load, epoch assignment, fingerprint algorithm or other scene-command behavior was added.

Task transition records and completed results carry `scene_contract_sha256`; active_scene carries the transition operation ID and request digest. These fields participate in the existing receipt digest and persistence. The controller's path-plus-SHA request digest is unchanged. Replay verifies the full host after_identity, original request/result/current/active path and SHA, registered contract digest, full current contract and exact active transition. It makes no load/setName/save call, including when headless `hasUnsavedChanges()` is True. INTENT reconciliation verifies the same registered full contract at the original path and source SHA before the existing geometry/RBD/particle checkpoints; it accepts a proven scene when active_scene has not yet been persisted. Epoch/CAS and existing rollback remain in place.

Legacy low-level calls without an operation identity remain supported. V1/V2 contracts and legacy missing owned_roots use the existing contract verifier. An old completed formal task transition without the new contract/active-transition bindings is rejected because its prior snapshot state cannot prove the new path identity; no migration or receipt rewriting is performed.

Software boundaries expand only the newly modeled HIP/HIPNAME identity from the current hipFile.path while preserving raw string channels and frame tokens. Two Karma settings defaults use the H21 native-basis expressions. The engineering chain's existing _SETUP explicitly returns True for headless hasUnsavedChanges; the generic host retains its existing clean default for unrelated scene.open_hip compatibility.

Validation uses explicit bottom HOM/USD substitutes, with no DCC or native probe. implementation-red.log is the existing complete V2 saved-scene test driven through formal scene.reopen_task_hip: it fails ARTIFACT_STRUCTURE_MISMATCH on the pre-fix snapshot-path identity. implementation-initial-green.log is that exact test after the causal repair. It preserves 41 nodes, 18 locked-definition internal nodes, full contract equality and raw expressions. The final compatibility run also covers V1, missing owned_roots and the no-operation call.

The initial full controlled group passed nine methods and reached a test-only global fingerprint assertion failure (missing playbar/takes bottom APIs); implementation-core-attempt.log preserves it. Those bottom APIs were supplied in the same test, and the affected replay method was rerun alone. No production repair resulted from that test fixture correction. The transition/owned group passed 17 cases. Separate pure geometry/RBD/particle checkpoint regressions are recorded without starting real host processes.

The old geometry addon reopen fixture fails during build_preview with GRAPH_CONTRACT_UNVERIFIED / native render role/type drifted: geometry_network, before reaching save/reopen. implementation-regression-debug.log records current source and implementation-regression-baseline.log reproduces it with the immutable 19 addon, SHA 22c88201eb5928c89a0dfcaf3d6e4941929f0885cd72ca6d335cb48a1f0837b6 (identical to this repair's before SHA). This frozen-domain error was not changed. The initial mixed regression run was stopped after these repeated preconditions, and the relevant transition group was rerun independently using canonical /private/tmp.

The single eight-stage software chain, packaging/freeze and independent review belong to the main agent. Real H21 locked-node parameter behavior, actual DCC save/load/render and native pixel output remain unverified.
