# HIP path identity implementation

The task HIP still loads its immutable snapshot, then restores and reads back the original saved path before contract verification. Registration uses that original path and unchanged SHA. The controller request digest remains path-plus-SHA. Task record/result/active-scene contract and transition bindings, full host identity and complete saved-scene verification remain mandatory for replay, including headless hasUnsavedChanges=True. V1/V2, legacy missing owned_roots and no-operation calls remain supported; unbound old completed snapshot states fail closed.

The actual snapshot-load common exit now persists a post_load_identity, loaded snapshot binding, exact controlled load count and warnings into the existing INTENT with its lock, CAS and receipt digest. It verifies stable host identity, actual loaded snapshot path/SHA and the expected load callback count before recording. Reconciliation requires an exact current match to that persisted identity. Missing load proof, unknown epoch, foreign identity, snapshot-path state, incomplete/mismatched registered contract and parameter drift remain INTENT. A proven named scene can recover after either normal loading or the two-load warning path.

Normal reopening and reconciliation share _fx_finalize_task_reopen. It performs the same saved-contract rebind, task root lease transfer, executor generation handoff, manifest persistence, active_scene/transition binding and transition completion. The existing geometry/RBD/particle rebind transactions validate and restore their complete saved checkpoints inside the root lease fence, and their commit paths revalidate native facts/authorization. Task recovery uses those same fenced transactions. Other scene commands retain their existing reconciliation checkpoint path. Completion failure restores generation, saves and manifest; completed-then-raised restores the exact INTENT through the existing completion-token path. Lease restoration uses CAS and preserves concurrent successors. Recovery and replay perform no load, setName or HIP save.

Render submission now compares hipFile.path to the bound original saved path. The immutable snapshot must independently exist without a symlink and match its SHA, which must also match the active source SHA. Original source existence/SHA, active host identity, scene-contract digest and complete scene-contract verification remain required. The positive unit reaches a genuine QUEUED render record through the production submit_render/configuration/budget paths. Its supervisor started receipt is explicitly synthetic and signed in an isolated test directory; only the scheduler is an in-memory bottom-boundary substitute. No process is started and no original SQLite database is touched.

Software HIP/HIPNAME expansion, both H21 native default expressions, all 41 nodes and the 18 locked-definition internal nodes are retained. The engineering software chain fixture explicitly models hython hasUnsavedChanges=True; the unrelated generic scene.open_hip fixture keeps its existing clean-state compatibility.

Validation and exact commands/return codes are in implementation-validation.json. Original implementation facts, manifests and logs are preserved, with attempt1 manifest/summary/validation copies. Review regressions were reproduced through real dispatch fault boundaries: render submission rejected the restored original path; normal reconciliation completed without usable active state; warning reconciliation rejected the actual second-load epoch. These are recorded in implementation-attempt2-red-render.log and implementation-attempt2-red-reconcile.log. A test-only snapshot-permission setup failure is also retained. The first recovery rollback run exposed a nested non-reentrant lease lock and was interrupted; the CAS rollback was corrected and both recovery success and failure paths were rerun.

The affected render/recovery methods pass with the final post-load snapshot readback guard. A separate 20-case group passed the existing warning/name/rollback, unsaved replay, V1/no-operation compatibility, scene transition and owned reopen tests. The previously passed 79 pure geometry/RBD/particle checkpoint/registry cases are preserved; their implementations were not changed. The known old geometry build-preview type mismatch was already reproduced against the identical before-source SHA and remains outside this repair.

The main agent owns independent review, one eight-stage software chain, package/freeze and any new candidate. No real DCC, native probe, model, simulation, cache or render has run. Candidate 19 and 06–18 are unchanged. Real locked-HDA parameter behavior and native rendering/pixels remain unverified. Budget remains 8 starts, 120 seconds per start, 600 seconds total, 512 MiB, one heavy job and zero retry.

The final lock-composition correction removes only the task finalizer's redundant checkpoint calls and its unused reconcile flag. No validation was moved outside a fence, and no global lock behavior changed. The finite combination test uses real finalizer, registered rebind, all three domain transaction wrappers, actual immutable load/INTENT binding and outer root flock. Explicit registry/native metadata spies exercise commit and commit-failure abort; a lock guard rejects same-root recursion before a second flock can block. All six domain/outcome subcases reproduce recursion before the correction and complete or roll back afterward. This finite test proves lock composition and durable rollback; it does not replace the 79 retained checkpoint/native-fact tests or establish native DCC acceptance.
