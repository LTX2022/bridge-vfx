# H21 建图专项资源方案（已确认）

适用目标仍为H21.0.631、sphere_ground_v2、ACEScg：正式建图→保存→同进程重开与完整验证→可信停止→第二新进程冷重开。渲染、Nuke、HY3、全16域与主工程合入不在本方案内。

## 资源合同

| 项目 | 拟定上限 |
| --- | --- |
| 建图进程 | 240秒，包含准入/启动、前置、建图、保存、验证和停止 |
| 冷重开进程 | 120秒，包含准入/启动、加载、完整读回和停止 |
| 全轮累计 | 360秒，按原有可信账本计费，不在ready后重置 |
| 启动次数 | 最多2次；第一阶段成功且可信停止后才可启动第二次 |
| 停止预留 | 每阶段10秒，计入上述上限，使用持久截止线推导，不额外追加 |
| 空间及并发 | 输出/缓存/tmp/log合计512MiB，单作业 |
| 重试 | 自动重试0；失败、超预算或停止未知即封闭该轮 |

用户已确认“同意新预算，审核后执行”。240秒是本轮批准的上限，不是测得的完工时间，也不保证通过。旧范围已失败封闭，其消耗和原件保留，不使用旧剩余票据。

## 用户确认后执行顺序

1. 固定新资源合同和源码输入。保留所有原120秒默认及旧scope的schema/验证行为；新配置须由可信控制端固定，模型不得指定预算或可执行路径。
2. 最小接入建图专用预算：核查NativeScope、GraphJobService、worker和专项driver的实际预算入口，使新profile及持久deadline一致。不能只改一个常数，也不能全局把120改240；冷重开仍120，累计360和停止预留必须真正执行。
3. 复用现有scheduler、操作记录、监督器和账本，不新增并行执行系统。重试、错身份、未知停止占槽、已停释放、产物与全参数读回条件不变。
4. 仅作必要软件验证：旧默认/旧scope不变、新profile仅可信配置可用、角色期限及累计限制、停止预留、失败不启第二阶段、预算/授权漂移拒绝。Python3.11、隔离状态；不跑慢完整HOM或全16域回归。
5. 未参与对应实现的审核者复核最终差异、边界及冻结指纹。问题在同一任务内整改；只有通过才生成新review和未使用scope。
6. 若用户本次同时授权“按本合同完成实现和独立审核后执行”，主控在审核通过后激活唯一新范围，不再逐小项确认同一范围；任何资源或目标改变须重新确认。实际运行严格失败即停，不补票、不自动重试。
7. 交付实际HIP/冷重开结果；若失败，保留原始证据并准确说明首个阻断。软件通过、资源增加均不能代替HIP验收通过。

本方案已获本轮软件实现及独立审核后一次真实执行的授权。审核通过前不激活或启动；不改变旧scope、旧默认及既有消耗，不将本授权用于追加失败重跑。
