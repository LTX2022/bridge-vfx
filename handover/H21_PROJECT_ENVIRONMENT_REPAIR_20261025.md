# H21 新工程资源绑定修复合同

范围承接 [热路径修复计划](H21_HOTPATH_REPAIR_PLAN_20261024.md) 与 [首次保存上下文修复](H21_FIRST_SAVE_CONTEXT_REPAIR_20261024.md)。本轮只修软件；不得启动真实宿主。已关闭的 HIP240 范围和原始证据不变。原资源合同仍为建图240秒、冷重开120秒、累计360秒、最多2次启动、512 MiB、单重作业、零重试。

## 根因与实现边界

GraphRun 在正式保存时生成新的 UUID 工程路径；原生工厂资源参数包含 `$HIP`、`$HIPNAME`，保存改变其求值。严格保存合同因此检测到场景漂移。仅提前命名 graph worker 的 HIP 不能覆盖公共 `agent.fx.build_preview` 后的多次 SaveAs。

在新工程构建时，复用现有可信 output_root，为明确的资源角色配置稳定目的地：gallery 数据库、deep 输出、渲染 checkpoint；受影响的烟雾源计划另包括 solver checkpoint 目录及 basename。basename 仍为文件名前缀。共用一套 helper 接入注册图初始化与公共构建入口，保存/重开继续使用既有 API、操作记录和严格比较。

只处理新建未保存场景的实际原生工厂默认值；参数必须无驱动、无 keyframe、未锁定，相关输出开关关闭且原始资源不存在。既有保存、用户修改、启用输出或资源已经存在时，不迁移、不覆写。全部前置检查先于参数修改。图片输出、产品、帧、ACEScg、缓存授权及执行开关不变；配置不创建目录、数据库、缓存或渲染。

project_environment 的 task/root/role/raw 值、可信项目目录及摘要进入现有 manifest、场景合同和保存读回。目的地分类只接受已验证的具体角色、路径和用途；输入与恢复缓存仍核验内容。全局Stage默认gallery仅在实际HOM节点等价、LopNetwork/Lop类别、同版工厂默认、无驱动及无已有资源时单独分类，不能扩大成通用路径豁免。冷宿主的运行状态目录可以不同，工程资源继续绑定保存时的项目目录。路径范围继承正式控制端已有output_root配置，helper不新增独立执行授权或监督器预算证明。配置或发布失败恢复原参数、root userData 和 sidecar；恢复不完整进入 reconcile，不能返回成功或重新当作 fresh。

## 分工与验证

- 插件单写者：共用初始化、读回、精确资源分类及回滚；保留两快照、实际根围栏、新2.1/旧2.0合同及原保存身份约束。
- 消费端/夹具负责人：严格合同消费与最小原生 API 替身；无关逻辑不改。UI disabled 与 locked/writable 分开，依据同版官方 HOM 文档保留真实状态。
- 启动/证据负责人：内存 HIP 路径准备、原18检查点双时钟锚及静态原生来源；不额外采集或启动宿主。
- 两位独立审查者：分别审查状态/围栏/兼容及原生来源/软件边界，问题在本任务内整改。

核心验收：两条正式构建入口；公共入口连续两次不同 UUID 保存；注册图保存及完整冷重开；不同宿主状态根；用户值/旧保存/已有资源/驱动/开关开启的拒绝；参数、manifest、sidecar 失败回滚及不完整恢复；资源分类与真实输入漂移；热路径、旧回执、租约和预算的受影响回归。使用显式底层软件替身，不预置成功回执或工程。每次构建新的软件HOM宿主时，由正式addon初始化独立会话、进程代次和初始scene epoch；同一宿主的加载递增和插件重载稳定身份保留。导入失败恢复原HOM与共享状态。旧fake缺失的合法HOM方法仅在底层模型补齐。

## 原生事实与交付边界

H21 参数默认值和接口分别记录本机 HDA、官方帮助及 HOM 依据。H22 四个 HDA 字段已从实际22.0.459静态定义独立核对；gallery 默认值有同版帮助，精确 compiled HOM 模板类型/禁用条件尚未取得。软件替身中最小字符串 API 的声明不能充当该缺失原生事实，不能由 H21 证据改标 H22。

最终冻结同一源码的核心测试、双人只读复核、可逆差异及新未授权候选。新候选应为 PREPARED_NOT_AUTHORIZED、零启动；不激活、不重用旧授权。性能、实际 Karma HDA 完整性、HIP 保存/冷重开及完整工程闭环仍需另外的真实验证。完整 M1、HY3、视觉及生产状态不提升。
