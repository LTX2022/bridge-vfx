# Bridge

Bridge 是连接 AI 助手与 Houdini、Nuke 的本地工作流项目。它通过 MCP 提供工程选择、任务查询、受控提案和执行入口，并保留可编辑工程、产物及执行证据。

## 当前能力

- 查询已登记工程和原任务，读取已接收的工程文件与结果；运行中、失败或未知状态不会被当作完成。
- 在已有几何工程的受支持模板内观察、提案和修改；额外反馈使用绑定具体请求的有限许可。
- 在已验证的具体案例中保存 Houdini 工程，进行独立冷开、Karma 输出与 Nuke 下游处理。
- 读取符合原签名和产物校验要求的历史结果；被替代的历史产物只能观察，不能因此重新获得执行权限。

技术完成和目标验收分别报告：`COMPLETE` 表示技术流程完成，`goal_status` 可为 `PASS`、`FAIL` 或 `UNKNOWN`；视觉质量需要另行验收。

## 能力边界

Bridge 仍在开发，当前结果不代表所有 Houdini 节点、16 个领域、所有平台或任意素材都已通过验证。它**尚未证明可以仅凭任意教程自主拆解、学习并稳定复现完整成片**，也不保证创意质量达到参考视频。

工程模板、可编辑参数、宿主版本、预算和可用素材均受具体任务限制。无法验证的输入、旧签名或停止状态必须如实报告；不能通过新建任务、重置预算或重放失败操作绕过限制。真实宿主执行、渲染及模型调用需要按任务范围授权，并保留实际消耗与停止事实。

历史结果依赖原始许可、回执、源码快照及文件路径；知识总结不能代替这些文件。当前仓库不包含本机私有状态、凭据、原始素材和被忽略的 `outputs`，克隆仓库不会自动恢复历史工程或授权。

## 使用

1. 安装兼容的 Python（3.11 或以上）、Houdini 和 Nuke，并按许可及目标平台配置宿主。实际兼容性以具体案例验收为准。
2. 构建插件发行包：

   ```sh
   python3.11 tools/build_agent_plugin.py 0.4.23 --output /absolute/path/to/release --python-command python3.11
   ```

   当前工作目录可能包含与本机已安装发行包不同的开发改动；自行构建后应单独验证，不应将它等同于已验收的安装包。
3. 按 [插件安装与工程入口](docs/agent-plugin.md) 配置本地 marketplace、登记工程并使用 MCP。已有工程先选择工程、列任务，再用原操作 ID 查询。
4. 新建任务或真实执行前，检查目标、输入、授权和预算。不要把入口就绪当作宿主连接或作品验收。

本机已安装的 0.4.23 版本曾通过新消费者的历史结果读回检查；该结论只适用于当时登记的工程和安装包，不代表新的构建或其他环境已验收。

## 目录

- `agent-plugin/`：MCP 包装和插件入口。
- `packages/`：任务运行时及 Houdini、Nuke、工作流实现。
- `plugins/`：宿主插件。
- `skills/`：工作流指引和已验证经验。
- `tests/`：软件层测试。
- `docs/`：接口、安装和设计说明；[历史材料与证据边界](docs/history-and-evidence.md)。

旧交付和本地运行记录按原依赖保留。运行环境、产品目标与历史验收应分别核对。文件保存位置、清理结果和 GitHub 覆盖范围见 [文件保留与上传范围](docs/storage-and-publication.md)。
